# v0.1.0-alpha.1 — Release Notes (prepared, not published)

- **Effort:** E05 Readiness Gate, Section 6.
- **Status:** **Prepared only.** No package has been published to npm.
  `RELEASE_ENABLED` stays off (awaiting npm org + token, an external
  blocker documented since E03). This document exists so publishing is a
  mechanical "flip the gate and run the pipeline" decision when that
  becomes possible, not a fresh writing exercise.
- **Would be:** the **first real release train** this project has ever
  cut. Every prior "release" reference in this repo (kernel's
  `docs/quality/certifications/kernel-0.2.0-rc.md`) is an internal
  certification, not an npm publish.

## Highlights

CoreStack's kernel and platform packages have reached the end of E04
(executable behavioral contracts) plus a readiness/hardening pass, sitting
on top of a tenant-isolation certification completed at E03 exit. This is
the foundation layer — no product module (tenancy, auth, billing, etc.)
exists yet; this release is infrastructure only, intended for engineering
evaluation and as the base E05 (Tenancy) will build on.

**What's real and proven:**

- A zero-runtime-dependency kernel (`@corestack/kernel`) with 8 ports
  (Cache, RateLimiter, Logger, EventBus, UnitOfWork, Encrypter,
  ProcessedEventStore, IdempotencyStore), each with an executable
  contract suite (`@corestack/kernel/testing`) proven against every real
  adapter — not just documented, executable and reused across adapters.
- A platform package (`@corestack/platform`) with a full transactional
  outbox, migration engine, RLS-based tenant isolation (certified with
  residual risks), config validation, health/readiness computation, and
  Postgres adapters for 4 of the kernel's ports.
- A golden-path example module (`examples/acme-crm-module`) proving every
  tenant-isolation touchpoint end-to-end against real PostgreSQL 18.
- 461 tests, zero mocked Postgres behavior anywhere — every database
  claim is verified against a real instance (local or Testcontainers).

**What this alpha is not:** a deployable product. No HTTP layer, no
authentication, no real feature module. See "Recommended audience" below.

### Version-numbering note

Kernel's internal certification doc calls it "0.2.0-rc" — that number was
assigned before this project settled on `0.x.y` alpha-channel numbering
for the first public release train. Resolving this naming mismatch (does
kernel ship as `0.1.0-alpha.1` matching platform, or does its own
internal numbering carry through?) is a decision the actual maintainer
release checklist below flags — **not resolved in this document**, since
it's a judgment call for whoever executes the real release, not a
readiness-gate finding.

## Breaking changes

None — this is the first release. Every future breaking change follows
`docs/engineering/09-release-versioning.md`'s pre-1.0 policy (minor may
break, patch never does, every breaking minor ships migration notes).

## Security

- ADR-0020: `IdempotencyStore` now requires `organizationId` (fixed a
  real, never-exposed cross-tenant replay vulnerability found during the
  Tenant Isolation Certification).
- ADR-0022: `Logger` adapters now redact `SENSITIVE_LOG_KEYS` at runtime
  (defense-in-depth behind the existing static lint deny-list).
- Full posture: **Certified with residual risks** —
  [tenant-isolation-certification.md](../security/tenant-isolation-certification.md),
  [security-scorecard.md](../security/security-scorecard.md). Highest
  open item: no real deployment has ever connected as the restricted RLS
  `app`/`platform` roles (Residual Risk R3) — proven correct, not yet
  proven live.

## Known limitations (carried forward, still true)

See [v0.1.0-alpha-readiness.md](v0.1.0-alpha-readiness.md) for the full,
still-current list (Redis `Cache` deferred, no real HTTP layer, no
authentication module, coverage not CI-gated, performance visibility
narrow). Nothing in E04 or this readiness gate changed any of those.

## Recommended audience

Unchanged from the readiness review: **internal engineering evaluation and
architecture review** — engineers deciding whether CoreStack's patterns
fit a future project, and contributors building E05+ on this foundation.
**Not appropriate for production deployment** — no authentication module
exists to gate a real HTTP surface, and Residual Risk R3 (real RLS
credentials) is unresolved.

## What changed since the last readiness snapshot (2026-07-29 → 2026-07-30)

- All 8 kernel ports now have executable contract suites (previously:
  framework existed, `Cache`/`RateLimiter` only).
- Contract-coverage audit, snapshot governance, consolidated performance
  baselines, Testcontainers readiness prep, export-surface audit, and a
  contributor "how to add a new adapter" guide were all added.
- Export-surface snapshot coverage closed (was gap: only kernel's main
  entry was gated; now all 5 conditions across kernel/platform are).
- 3 of 4 previously-unproven contract suites gained real mutation proof
  (Cache, RateLimiter, Encrypter); `UnitOfWork` remains a deliberate,
  reasoned deferral.
- Test count: 454 → 461.
